# 个人网站定位与视觉改造设计

日期：2026-11-02

## 1. 目标与受众

将当前混合了私人任务管理、笔记、动态和工具的网站，改造成面向朋友与熟人的个人主页。

首次访问者应能快速了解：Jasper 是谁、最近的生活与文字、做过的小东西，以及如何联系。网站不再以求职作品集或私人效率工作台为主要定位。

已确认的产品决策：

- 主要受众是朋友与熟人，而非招聘者。
- 保留记忆碎片和文章笔记，两者都是主要公开内容；笔记界面不再参照 Obsidian。
- 采用“温暖生活杂志”的视觉方向。
- 删除任务管理与项目工时追踪。
- 所有现有小工具保留，但入口降为次级，不作为主要功能。

## 2. 功能取舍

### 保留并强化

- 首页个人介绍、真实兴趣与联系方式。
- 记忆碎片：保留现有发布、点赞、评论和云端同步行为，并提供独立页面。
- 笔记：对外不再使用 Obsidian 名称或文件库式界面，改为独立、精美的文章阅读页；核心支持标准 Markdown、GFM 与 LaTeX，并提供独立页面。
- GitHub：只展示真实仓库信息，作为“我做过的小东西”的次要分区。
- 深色模式、中英文切换及必要的管理登录能力。
- 星空彩蛋及其子路由，并将页脚签名末尾的四角星装饰作为隐藏入口：平时融入排版，悬停仅出现淡星芒与细轨道，点击进入 `/starry`；不显示“彩蛋”文字，不进入主导航，支持键盘与屏幕阅读器标签。

### 保留但降级入口

以下小工具继续保留现有路由与功能：

- `/internship`：实习决策助手。
- `/text-segmenter`：英文分段器。
- `/movie-recommender`：每日电影推荐。
- `/devtools`：开发工具。
- `/git-conda-guide`：Git & Conda 指南。
- `/tools`：小工具索引页。

`/tools` 不再出现在主导航或首页主要按钮中，只在页脚和移动端次级导航提供低调入口。工具页本身可后续做轻量视觉适配，但本轮不重写各工具业务逻辑。

### 删除

- `/calendar` 任务管理及 `/projects` 项目工时追踪的前端路由、导航入口和专属代码。
- 只服务于上述功能的组件、Hooks、工具函数、种子数据、翻译及测试引用。
- 占位的 About 页面及“了解更多”空链接。
- 首页虚构的博客预览、技能标签、GitHub 统计和随机贡献图。
- 访客可见的登录、个人资料与彩蛋目录入口；`/login`、`/profile` 和 `/starry/*` 仍可直接访问。
- `/easter-eggs` 彩蛋目录页及路由。

### 删除边界

不删除或清空任何 Supabase 表、云端记录、Storage 文件或浏览器现有 localStorage 数据。代码删除只影响前端功能，不执行数据销毁或数据库迁移。

## 3. 信息架构

桌面主导航只保留：首页、记忆碎片、笔记。语言与主题切换继续保留；搜索在支持笔记与公开内容检索时保留，并清除已删除功能的索引项。

页脚提供：小工具、GitHub、邮箱及用户已配置的真实社交链接。登录和彩蛋不占公开导航。

首页顺序：

1. **个人封面**：称呼、简短自我介绍、头像或已有生活照片，以及“看看我的动态”按钮。
2. **关于我**：真实的所在地、兴趣、近期关注与一段自然短文；未提供的资料使用中性提示，不编造个人信息。
3. **最近的生活**：最多 3 条近期记忆碎片，突出照片和短文，并链接完整动态页。
4. **最近写的东西**：最多 3 篇近期笔记，展示标题、摘要与日期，并链接笔记页。
5. **我做过的小东西**：少量真实 GitHub 仓库；接口失败或无内容时简洁降级。
6. **联系方式**：真实公开账号和邮箱，不显示示例地址。

移动端保持相同阅读顺序，改为自然单列。

## 4. 视觉设计

### 色彩

以奶油白为页面底色，深墨色为正文，陶土橙为主要强调色，鼠尾草绿用于少量标签。深色模式提高正文和次要文字对比度，避免小字融入背景。

沿用项目 Tailwind 主题变量，集中修正颜色语义，不为各分区创造互不一致的新色板。

### 字体与排版

中文正文使用清晰的现代黑体，英文展示标题可保留衬线字体。建立明确的标题、导语、正文、辅助文字层级；增大关键正文，控制长文行宽，避免首屏标题过大和无效留白。

### 首屏与内容形式

首屏采用杂志封面式左右布局：文字与行动按钮在一侧，头像或已有图片在另一侧。首屏无需占满整个视口，访客首屏即可看到有效介绍。

动态使用照片和自然留白，笔记采用编辑式列表，项目使用轻量仓库条目。减少所有内容都被相同圆角边框卡片包裹的情况。

### 笔记与文章阅读

笔记不再参照 Obsidian 的文件库、双链或知识管理界面，对外统一称为“笔记”或“文章”。新公开路由使用 `/notes`，旧 `/obsidian` 链接重定向到对应的新地址，避免已有分享链接失效。

文章列表以标题、摘要、日期和少量标签为主。阅读页采用舒适的文章行宽、明确标题层级、精致引用与分割线、响应式图片、带复制按钮的代码块，以及居中的独立 LaTeX 公式；行内公式不得撑破段落。桌面端可显示轻量目录，移动端目录折叠，长公式与代码允许横向滚动。

渲染能力聚焦标准 Markdown、GFM 和 LaTeX，保留代码高亮。Wikilink、标题折叠、Obsidian Callout 等专属语法不再作为新界面的设计要求；已有笔记原文和云端数据不修改，不批量重写内容。

### 动效与可访问性

删除打字等待和逐标签入场动画，只保留轻量淡入、照片悬停与必要页面过渡。尊重 `prefers-reduced-motion`。

保留语义标题、键盘操作、清晰焦点、图片替代文本和足够色彩对比。移动端不缩小正文，不让装饰影响点击与阅读。

## 5. 组件与数据设计

### 主要改造点

- `app/src/App.tsx`：删除任务路由与彩蛋目录路由，保留小工具、管理登录和隐藏星空路由；移除任务种子数据初始化；增加 `/notes` 与旧笔记地址重定向。
- `app/src/components/Navbar.tsx`：收缩主导航，整理移动端次级入口，清理搜索与公开账号入口。
- `app/src/components/Footer.tsx`：加入低调的小工具入口和真实联系方式。
- `app/src/pages/Home.tsx` 与 `app/src/components/home/`：重做首页分区，新增近期动态和精选笔记组件。
- 笔记列表、阅读页和 Markdown 组件：移除 Obsidian 界面范式，完成文章化排版，继续支持 Markdown、GFM、LaTeX 与代码高亮。
- `app/src/data/site.ts`、`app/src/data/about.ts`：移除虚构默认展示数据，保留仍有消费者使用的可编辑资料能力。
- 全局搜索、翻译、SEO、页面标题和页脚链接同步更新，不在访客文案中出现 Obsidian。
- 删除任务与项目追踪的孤立代码；保留仍被其他功能共享的通用存储、类型与工具。

### 数据流

首页个人资料继续通过现有本地设置与 Supabase 后台同步机制读取。

近期动态复用现有 Moments 数据访问方式，首页只读取并展示少量最新公开内容，不复制一套发布或评论逻辑。点击后进入完整动态页。

精选笔记复用现有 `notes` 表和数据客户端，只读取少量最新笔记元数据和必要摘要。内部实现可复用现有读取逻辑，但页面命名、导航与文案统一使用“笔记”。摘要不得把 Markdown 标记或 LaTeX 公式源码直接暴露在列表中，中文标题与 URL 编解码必须正常。

GitHub 仓库继续通过真实 API 获取并经过现有 Zod 验证。删除随机贡献图、虚构 star、repo、streak 和无真实来源的统计。

### 空态与错误

个人介绍与联系方式不依赖远程内容，始终可用。动态、笔记或 GitHub 请求失败时，仅对应分区显示简洁空态或隐藏，不弹出阻塞错误，不影响其他分区。

保留现有 Supabase 静默降级约定；不得在删除功能时改变 Moments 的本地优先、后台同步和先删云端再更新本地的行为。

## 6. 测试与验收

更新受删除和首页改造影响的现有测试；保留功能的核心 Hooks 和工具测试不得为了通过而删除。若新增数据选择或摘要工具，按项目现有 Vitest 约定补充测试。Markdown 与 LaTeX 测试覆盖中文标题、行内/块级公式、代码块、列表、引用、表格和长内容溢出。

必须执行：

```bash
cd app
npm test
npm run build
```

浏览器实际验证：

- 首页首屏、各内容分区及真实链接可用。
- 记忆碎片原有阅读、发布与管理路径不回归。
- `/notes` 的文章列表和阅读页美观可用，Markdown、GFM、LaTeX 与代码高亮正确，旧 `/obsidian` 链接正常跳转。
- 小工具可通过次级入口访问，五个工具路由均可用。
- 主导航、页脚和搜索结果不存在任务管理、项目工时或彩蛋目录残留，公开界面不出现 Obsidian 名称。
- `/login`、`/profile` 可直接访问，星空隐藏路由仍可访问。
- 已删除路由不显示旧页面，且不会产生 JavaScript 异常。
- 移动端、桌面端、深色模式和减少动态效果设置可用。
- 动态、笔记和 GitHub 请求失败时，首页其余内容仍正常显示。

## 7. 非目标

- 不重写五个小工具的业务功能。
- 不更换笔记存储后端，不迁移或批量改写已有笔记原文。
- 不修改 Supabase 数据库结构或销毁数据。
- 不引入新的后端、CMS 或 UI 框架。
- 不编造用户个人资料、照片、项目成果或社交账号。
